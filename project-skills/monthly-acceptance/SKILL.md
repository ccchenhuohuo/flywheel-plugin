# 大盘数据验收

**冻结范围 → 全景扫描 → 独立候选 → 按影响调查与反证 → 覆盖核验 → 结论分点与证据 → 封存。** 程序确定必须检查的分母和计算；模型解释证据、提出与检验假设、判断影响和使用边界。调查可以开放，基础覆盖不能任选。

先读 [执行契约](references/execution-contract.md)，按当前包冻结的版本运行。业务方法详见 [methodology.md](references/methodology.md)，人工理解可打开 [可视化说明](references/acceptance-guide.html)。

## 业务口径

- 观察单位为国家 × 公司标准完整类目路径 × 月份，中国合并淘宝与天猫；SPU 是 product_id，Amazon 为 parent_asin，SKU 用于必要的原始规格和父子归属核查。
- 四项结果分别为 SPU 数量、SPU 价格带、销量、本币销售额。销量独立排序；平均价格不能替代分布，低金额不能豁免数量、销量或价格带失真。
- 主分析 `internal.flywheel.monthly_sales_with_dim`，回溯 `internal.flywheel.monthly_sales_wide_new`。with_dim 是标准类目代理，不等于最终发布面。原始采集范围单独守门；映射重复、冲突先核对，不把放大求和当有效结果。
- 只读 Doris，不修改数据或治理层。估算金额不等于实际成交额；无观测不等于零。不同国家金额不相加，同一层级使用互不重叠的路径，跨层 SPU 重新去重。

## 必须执行的路线

1. **冻结。** 读 `验收/config.yaml`、`项目范围.md`，显式确定月份；`acceptance_run.py start --month YYYY-MM` 建立包。所有历史月份、国家/L1/L2/L3、自然月环比/同比、价格带与初始阈值预先固化。后续命令使用 `<RUN>/inputs/skill/scripts/acceptance_run.py`，不能在原包更改政策或缩减任务。
2. **扫描与独立观察。** 执行 `scan`、`analyze`。检查到货、原始范围、完整键、四项结果、品牌/SPU 贡献与正负抵消、进出及固定语义样本。程序生成全部候选和覆盖矩阵，分页展示不缩小召回。失败任务恢复后重跑；缺查询、缺页或缺同比都不得宣布全景完成。独立候选冻结前不加载旧原因判断。
3. **调查。** 读 cases 与 candidates，优先当期、重要影响和范围/身份问题，保留其余候选去向。沿不重叠的细类目、品牌、SPU 找变化贡献；同时看旧头部、新头部、销量与金额绝对变动，兼顾量价抵消。用 `drill` 取得完整双期 SPU 明细，用 `query` 做只读取证。按 [方法](references/methodology.md) 提出开放市场假设并检查反证，必要时追到原始细行。外部证据与本品对拍见 [cross-validation.md](references/cross-validation.md)。尾部停止要说明四项残余影响；未证实的原因保留待核。对固定语义样本逐组记录核验，稳定但错误的数据同样可能被发现。
4. **处置与历史重验。** 用 `record` 为每个候选留下范围、事实、证据、反证、继续/停止理由与下一步；相关候选可合并判断但不得丢 ID。独立观察后重验开放历史问题，单列独立召回与历史提示补查。缺完整契约、内部数据或外部幅度证据时明确限制，不伪造正常。没有付费外部查询授权时继续现有证据范围内的工作。
5. **收尾与交付。** 最后一次数据查询后 `finish-scan` 复核指纹，随后 `validate`。模型按 [报告写法](references/report-writing.md) 编写 report-content.json：开头分点结论，每个问题在一处写明变化/影响、充分事实、证据与反证、判断和行动。`render` 生成一篇自足报告及执行看板；看板用于观察覆盖、轨迹、候选与证据。核验未完成时继续修复可完成事项，证据限制则明确保留。`seal` 将执行状态、使用判断与文件哈希一起封存；封存不表示业务通过。补查建立关联运行，报告与证据只落盘。

## 调查与表达边界

贡献只定位变化，不证明错误。价格带变化区分同 SPU 变价与商品/销量结构迁移；市场合理性不等于异常幅度已经得到解释。整体需求、渠道迁移、采集/映射变化可以叠加；当前平台节点不能证明历史覆盖。外部框架保持开放，按“外部变化 → 行为/供给/交易结构 → 相关类目/SPU → 四项结果”检验传导，不为未核实的倍数编造市场故事。

最终报告区分已核正常、触发信号、未观察、未执行、待核；读者不用打开原始明细也能理解重要结论。重要问题不以 Top-N 截断，报告合并同因问题但保留覆盖关系。不自动发送反馈或更新治理发布；仅用户另要对外稿时生成反馈草稿。
