# 沿排查路径呈现完整验收

面向业务读者回答：类目 SPU 数、价格带、销量、销售额是否可信；哪些局部变化决定了结果；证据支持什么原因。先呈现结论与重要问题，再沿调查推进顺序展开证据与判断。章节、图表可自由组织，下面的完整性要求始终适用。

## 完整路径与可见性

正文交代本次边界与到货/批次一致性、全历史范围、四项结果、贡献与头尾取舍、解释和源数据追查、内外部核验及最终使用结论。每个环节写清**查什么/覆盖哪里、看到什么/证据在哪、支持什么判断、为何继续或停止**；一条问题跨多个层级时保持关联，避免把原因和结果散落在不相连的清单里。这是可复核的决策依据，不要求记录逐次工具调用或探索中的全部草稿。

已查且未发现问题的环节必须在正文直接可见，不用折叠区、隐藏页、仅附链接或“其余正常”替代。同口径正常对象可合并表达，但要说明范围、关键观测与证据；完整明细可附文件。低影响尾部也保留可见的总体影响与停止理由，无须逐项罗列产品。

状态分清：已查未发现问题、已确认异常、待核、无观察、未执行/未覆盖、按当前证据无需进一步核验。必要路径缺输入或未完成也要显示原因及其对结论的限制；可选工具未调用不自动构成缺陷，但应说明对应问题是否需要外证。只审了部分范围，就只对该范围作结论。

## 证据与表达

- 开头说明本次运行、数据时期/国家/类目口径、实际覆盖与总体结论。分别评价四项结果；未到货、无观察、未执行、截断或证据不足不得写成全部通过。区分输入批次或只读导出的一致性证据与仅关键指纹未变，写明收尾复核及限度。
- 每个主要问题连起来讲：**结果变化 → 子集增减件数/金额与贡献 → 为什么优先 → 逐层取证与反证 → 定性/置信 → 对四项结果及公司使用的影响**。区分类目变化贡献与经核验的错误额影响；不要把可疑商品全额或全部增量直接算成错数。
- 贡献注明父类目、两期、国家、件数/本币单位及分母。净变化接近零时展示件数/金额和正负抵消，不硬解释比值；多个层级影响不重复加总。
- 头部围绕主要销售额组成解释，不固定榜单长度；兼顾本期与历史头部。价格带展示商品数与销售额组成，均价只作辅助。
- 四项结果均不受实质影响的尾部问题合并为风险提示，不逐条罗列。若影响销量、SPU 数量、价格带或重要范围，就说明为何需要升级。
- 事实、供应商声明、我方推断分开；旧观察只作注明来源的比较。外部驱动按本次发现组织，说明假设、传导、对应地区/时期的证据与反证及其边界，不按事件类型填章节。区分整体需求、渠道迁移和采集变化；趋势合理性与幅度是否可解释分开。确认的数据问题按影响进入审计报告，未解释项保留待核，不堆新闻或虚构影响倍数。
- 本品对拍缺数据时如实标注；不得用平稳画像替代内部对拍，或把相符当独立证明。
- 正文用业务语言和完整月份，注明平台/公司类目轴。报告讲影响与限制，行动请求放反馈草稿；报告不自动发送。

运行包中至少保留 `run.json`、`观察.md`、`报告.md` 和 evidence 下实际查询/结果；反馈按需生成。总结的检查范围应能回到证据，不要求机械记录无关参数或按工具数量证明完成。

## 交付复核

对照独立观察和本次证据，从读者视角检查完整路径、正常环节可见性、四项结果、贡献守恒、事实/推断边界以及结论限制。报告末尾简述复核结果；发现证据缺口就补查或保留限制，不用“已完成”代替。`seal` 只检查文件存在与哈希，不能替代这次内容复核，也不判定放行。

反馈草稿每条：具体范围与商品/平台路径、结果如何被影响、已核证据、希望供应商核对/说明什么。推断写疑似，不替服务商断言根因。
