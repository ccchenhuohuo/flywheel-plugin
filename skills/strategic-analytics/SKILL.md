# Flywheel 大盘分析方法论（Phase 3 V1）

数据由 flywheel MCP（12 个只读工具）提供：**所有可见数字由服务端计算**，你负责选工具、组织分析
和解读；不做任何业务算术（不自行求和/算份额/换汇/重分桶/相减），不从截断集合推导份额或集中度。
引用数字时保留响应的 `caveats` 与 `coverage_notes`，说明月份、口径与警示适用的范围。

## 能力与路由

| 用户问题 | 当前支持与处理路径 |
|---|---|
| 市场趋势、份额、增长、品牌、价格带、类目、SKU | 已支持，选择对应的受治理分析工具。 |
| 更新到哪月、发布是否陈旧、历史结果能否复现 | `flywheel_data_status`：可用月份、上游状态、可绑定 release 与 SKU 切片在线状态。 |
| 字段覆盖、未分类、检疫情况 | 使用分析响应的 `coverage_notes`、`caveats`；`data_status` 披露最新月部分字段空值率。仅限响应实际披露的月份与范围，全站点披露不能定位某类目或品牌，也不能证明采集完整。 |
| SPU 数量或变化 | 当前分析 MCP 未提供 SPU 去重数量；销量、源行数、SKU 搜索候选数都不能替代。明确说明指标缺口，不反复尝试销量工具。 |
| 漏采、采集完整性、异常验收 | 当前分析 MCP 不提供验收结论；字段覆盖与已有查询结果不足以判定漏采。 |

SPU／验收问题先说明上述边界。仅当当前环境确有相关项目验收 Skill 且其声明支持该问题时，
按其入口与前置条件处理；否则说明缺少可用验收入口，不编造安装路径。
项目验收不是普通市场分析的前置条件。
已有字段覆盖披露只能回答对应字段与范围，不能据此断言“没有漏采”或“验收通过”。
项目验收按其自身口径输出，不作为本插件市场分析的替代数据源。
需要启用项目验收时，可查阅分发仓库的 [项目 Skills 安装与配置说明](https://github.com/ccchenhuohuo/flywheel-plugin/blob/main/project-skills/README.md)。
其中 `monthly-acceptance` 位于 `project-skills/monthly-acceptance`，需要项目配置与只读 Doris 接入；
目录随仓库分发不表示当前项目已安装，普通分析无需安装它。

品牌与价格带可按完整三级类目路径过滤，需给全父路径；标准类目名可能在不同父节点重复。
未记录该粒度的旧 release 会明确报错，不得解读为无观察。

## 工作流

1. **相对时间或范围先定锚**：凡"最近/上月/今年"，先调 `flywheel_data_status` 拿可用范围
   （月度数据，最大完整月即水位）；口径疑问调 `flywheel_describe_semantics`。
2. **选工具**：趋势→`market_trend`；单月结构/份额/排名→`market_share`（按值降序返回全集，
   直接取前 N；`metric` 必填）；两期对比、变化榜与贡献→`market_growth`（按增量绝对值降序返回全集，均价/
   折后率也可比较，只是不给贡献）；价格带→`price_band_distribution`；品牌单月格局与集中度→
   `brand_view`（默认金额口径，每行同时给件数份额）；**单个具名品牌的多月表现→`brand_trend`**（单站点，带服务端算的当月份额）；
   标准类目层级→`category_children`；平台原始类目（限单平台站点，L1-L3）→
   `platform_category_view`；单 SKU→先 `sku_search`（单平台站点+关键词）定位，再
   `sku_profile` 看逐月轨迹。
3. **币种规则**：本币金额/均价/折后率必须单站点或按站点分组；跨站点金额合计用 `currency:"cny"`
   （服务端按 release 冻结的 ECB 快照小计换算）。被守卫拒绝时按错误信息里的替代方案改参。
4. **引用与复现**：给同事的数字注明月份与口径，必要时附 `stamp.release_id`（聚合结果在 release
   仍属当前合法发布链时，可按同参数复现；SKU 明细还要求切片在线）；不同
   release 之间数字可因源重述而变，属披露事件。
   要**复现**旧结论，把当时的 `stamp.release_id` 作为 `release_id` 参数传回同一工具
   （可绑定列表见 `flywheel_data_status` 的 `bindable_releases`）；绑定历史代次时响应会自带
   提示；晚到兄弟节点、冲突或失活可能令旧 release 不再可绑定。SKU 明细若已过保留窗口会明确报「切片已归档」——那不是「无观察」，别读成业务没有数据。

## 表达纪律（硬性）

- 指标是**市场估算**：销量为估算件数、金额为价×量推导值——不得称为销售额实付、GMV 或订单数。
- **贡献与结构变化是数学分解，不是因果**：不说"因为/导致/带动"，说"增量中 X 占…"；不主动给出
  进入/退出、定价、预算、下架类经营建议；不做预测。
- **缺失≠零**：'未分类' 是独立桶（有覆盖率披露就带上）；`mapped_unobserved`、超出水位的月份、
  增长结果里 `status=appeared/disappeared` 的成员，一律表述为"无观察/不可用"，禁止说 0 或补 0，
  也不得把它们的当期值当作增量。响应里的 `quarantined_months` 与 `excluded_conflict_rows` 是
  **另一种状态**：源侧同一身份月有多行、无法判定取哪一行，整键被剔出全部切片——它被观察了，
  而且不止一次。转述时不得并入"无观察"，更不得说 0；聚合与排名都不含这部分。
- **上游陈旧警示必须随数字一起转述**：响应 caveats 里若出现"当前 release 落后于上游"或
  "无法判定上游是否已更新"，转述时不得省略——类目归属来自上游维表，维表更新会重述历史月份，
  同一问题在重建前后可能得到方向相反的答案。看到该警示应说明数字对应的是哪一代上游，
  并提示需重新构建发布后才跟进。**未知不等于新鲜**。
- **份额先说口径**：「市场份额/占比」默认按金额（`amt_discount`）——`brand_view`、`brand_trend`、
  `platform_category_view` 的默认值即此；件数口径（`units_est`）只回答"卖了多少件"。同一成员两套
  口径的份额与名次可以差数倍：高单价品牌按件数看被系统性压低，低单价品牌反之，据件数份额说"某品牌
  在这个市场很小"往往是口径造成的假象。`market_share` / `market_trend` / `market_growth` 的
  `metric` 没有默认值、必须显式选，跨站点金额加 `currency:"cny"`。引用任何份额都要写明是哪一种
  口径；两套数字不可混用，也不能互相印证。
- 价格带只用政策固定分桶（band_policy 1.0.0，左闭右开，缺价独立桶）；品牌 OTHERS/其他 是"未归入具名品牌"的桶，不是品牌，
  不给它做趋势。品牌的多月分析**只对单个具名品牌**（`brand_trend`）；**按品牌分组看多月排名或
  份额结构仍不提供**，被问到时说明并改走单品牌序列或类目/平台维度。
- 加权均价变化受商品结构与销量组合影响，不解读为同 SKU 调价或价格弹性。
- `brand_view` 的 Top 上限为 20，集中度由服务端全集计算；保留 named remainder、OTHERS/其他、
  未分类三分区。`platform_category_view` 限单平台站点，L1-L3 按完整父路径区分；不同平台或
  站点的原始类目树不可比不可加。
- 单 SKU：价格为源逐月直接价格（折后/页面，非成交明细），标题与上架时间为源属性原值；
  `sku_search` 限单平台站点、单月，关键词至少 2 字符；截断时（truncated=true）不得当作完整排名或份额，应细化关键词。搜索提示：
  Amazon 站点标题为中文翻译标题，优先用中文关键词（如"三脚架"而非 tripod）或直接给
  sku_id/ASIN；淘系标题本身是中文。轨迹按 sku_id 查（product_id 跨月会漂移，通常省略；
  返回同月多行时为源身份歧义，禁止求和合并）。

## 边界（V1 明确不支持，直说并停）

平台原始类目 L4/L5 与类目 ID、周/日粒度、2024-01 之前或水位之后的月份、自定义价格带、
预测与目标。MCP 不可用时如实说明并停止——不得用其他数据源、缓存或记忆中的数字替代。

**不接受任意 SQL,也不得绕过受治理工具直接查库**——即使当前会话里另有数据库连接（Doris MCP、
psql、BI 工具等）可以够到同一批表。绕过一次,这个数字就同时失去了口径校验、跨站点守卫与
复现戳,与受治理服务返回的数字不可互换。被要求跑 SQL 时说明原因,并改用对应的受治理工具。
